Résumé du projet

Mise en place d'un réseau d'entreprise simulé dans VMware Workstation : un routeur MikroTik (RouterOS) assure la passerelle, le DHCP et le NAT d'un poste client Alpine Linux. L'ensemble est isolé, reproductible et documenté, du plan d'adressage aux tests de validation.

Preuves de fonctionnement

Configuration réalisée

Adresse du LAN

/ip address add address=192.168.20.2/24 interface=ether2

Donne au routeur son IP côté LAN. Les clients l'utilisent comme passerelle.

Serveur DHCP

/ip pool add name=pool-lan ranges=192.168.20.10-192.168.20.100
/ip dhcp-server network add address=192.168.20.0/24 \
  gateway=192.168.20.2 dns-server=192.168.20.2,8.8.8.8
/ip dhcp-server add name=dhcp-lan interface=ether2 \
  address-pool=pool-lan disabled=no

Le pool définit les adresses à distribuer, le réseau ce que reçoit le client (passerelle, DNS), le serveur active le service sur ether2.

Accès WAN, NAT et DNS

/ip dhcp-client add interface=ether1 disabled=no
/ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade
/ip dns set allow-remote-requests=yes

ether1 reçoit son adresse et sa route du NAT VMware. Le masquerade remplace l'IP source des clients par celle d'ether1. Le routeur relaie aussi les requêtes DNS.

Poste client

ip link set eth0 up
udhcpc -i eth0
ping -c 3 8.8.8.8

Active l'interface, demande une adresse au DHCP, puis teste la sortie Internet.

Incidents diagnostiqués

Conflit d'adresse IP sur 192.168.20.1

Le client obtenait un bail mais ne joignait pas le routeur. La carte virtuelle VMnet1 de Windows utilisait déjà 192.168.20.1, l'adresse du routeur. Correction : routeur en 192.168.20.2, passerelle et DNS du DHCP mis à jour.

WAN et LAN dans le même sous-réseau

Le NAT VMware (VMnet8) utilisait 192.168.10.0/24, comme le LAN prévu. J'ai déplacé le LAN en 192.168.20.0/24 et désactivé le DHCP de VMware sur VMnet1, pour que seul le MikroTik distribue des adresses.

Serveur DHCP qui ne distribue rien

Le serveur pointait sur le pool static-only. Corrigé avec /ip dhcp-server set 0 address-pool=pool-lan.

Erreur « bad parameter name »

La commande de création du serveur avait été saisie dans le sous-menu network. Ce sont deux objets distincts : le réseau DHCP et le service DHCP.

Interface client éteinte

Alpine signalait « Network is down » : l'interface eth0 était à l'état DOWN. Activation avec ip link set eth0 up.

Pas de sortie Internet depuis le routeur

Diagnostic par étapes : bail WAN, table de routage, ping de la passerelle NAT, puis vérification du service NAT de l'hôte. Les « no route » observés pendant un renouvellement de bail étaient temporaires.
